## 2. Understanding & Architecture Analysis

### Fixed-Cost Droplet Architecture vs Consumption Billing
DigitalOcean App Platform and Managed Database DBaaS clusters introduce variable consumption billing that fluctuates with CPU utilization, memory allocations, and query volume. To optimize utility and cost-effectiveness, AdventureTogether has migrated to a **dedicated Virtual Machine (Droplet)** deployment model located in DigitalOcean's **SFO (`sfo3` - San Francisco 3)** datacenter region.

### Key Objectives Solved:
1. **SFO Datacenter Targeting (`sfo3`)**: All cloud resources (VPC, Droplet, Static Reserved IP, Cloud Firewall) default to `sfo3` with private `10.10.0.0/16` subnetting.
2. **Predictable Droplet Sizing Tiers**:
   - **Standard Production (Recommended)**: `s-2vcpu-4gb` ($24/month, 2 vCPUs, 4GB RAM, 80GB SSD, 4TB transfer) providing balanced memory allocation (~1GB PostGIS, ~600MB Django, ~500MB Worker, ~100MB Nginx, ~1.8GB OS/caching headroom).
   - **High-Capacity Concurrency**: `s-4vcpu-8gb` ($48/month, 4 vCPUs, 8GB RAM, 160GB SSD, 5TB transfer) for city-wide concurrent hunts.
   - **Development / Staging**: `s-2vcpu-2gb` ($18/month, 2 vCPUs, 2GB RAM, 60GB SSD, 3TB transfer).
3. **Resilience & Memory Spike Protection**:
   - Allocated a **2GB SSD swapfile** in Cloud-Init to prevent kernel OOM kills during heavy geospatial polygon clipping and OSM Changeset ingestion.
4. **Complete Single-VM Stack Orchestration**:
   - Executes all 4 core services (`db` PostGIS 16-3.4, `backend` Django 5.x REST API, `worker` Django-Q2 harvester cluster, and `frontend` Vue 3 / Nginx) using `docker compose` managed by a native systemd unit (`adventuretogether.service`).
5. **Security & Backup Hardening**:
   - Double-layer firewall protection: DigitalOcean Cloud Firewall at the edge (inbound 22, 80, 443 only) + Host UFW + Fail2ban SSH jail.
   - Automated daily PostGIS dumps at 02:00 UTC with 14-day rotation and weekly Droplet cloud image snapshots.
   - Automated Let's Encrypt TLS issuance via Certbot.
