### Understanding of the Task
The objective was to implement the architectural delivery plan for automated DigitalOcean Droplet deployment and update lifecycle for AdventureTogether:
1. **Root Cause Resolution for "Blank Nginx Site"**:
   - In Cloud-Init (`deploy/digitalocean/terraform/templates/cloud-init.yaml.tftpl`), the apt package `python3-certbot-nginx` previously caused Ubuntu to install and start the host Nginx daemon on port 80, masking the frontend Docker container.
   - Initial bootstrap was missing automated Django migrations (`python manage.py migrate --noinput`).
2. **Automated Terraform-to-Ansible Bridge**:
   - Ensure generated ED25519 SSH private keys are persisted locally with `0600` permissions (`deploy/digitalocean/terraform/id_ed25519`).
   - Export Ansible outputs (`ssh_private_key_path`, `ansible_inventory_content`, `ansible_deploy_command`).
   - Enhance `deploy/digitalocean/scripts/deploy.sh` to extract the SSH key, dynamically generate `deploy/ansible/inventory.ini`, and optionally run `ansible-playbook` automatically (supporting `--skip-ansible`).
3. **Ansible Playbook & Role Upgrades**:
   - Update `deploy/ansible/roles/application/tasks/main.yml` and `playbook.yml` to template production `.env`, synchronize codebase, start systemd unit `adventuretogether.service`, run database migrations, and verify `/api/health/`.
   - Update `deploy/ansible/roles/security/tasks/main.yml` to ensure host Nginx is stopped, disabled, and masked.
4. **Dual Update Pathways (Zero Data Loss)**:
   - Remote on-Droplet updater (`/opt/adventuretogether/deploy/update.sh` / `deploy/update.sh`): Pulls latest `main`, rebuilds containers, runs Django migrations in an isolated container, collects static assets, reloads services gracefully (`docker compose up -d --remove-orphans`), and verifies API health check.
   - Local CLI update runner (`deploy/digitalocean/scripts/update.sh`): Auto-detects Droplet IP and SSH key, connecting over SSH (or Ansible) to invoke the update process.
   - Dedicated Ansible update playbook (`deploy/ansible/update.yml`).
5. **Testing, Documentation & Feature Registry**:
   - Extend `backend/apps/core/test_deployment_templates.py` with comprehensive unit and integration tests.
   - Update `documentation/digitalocean_deployment.md` and `documentation/deployment_guide.md`.
   - Record feature **FEAT-012** in `FEATURES.md`.

### 4. Ansible Playbooks & Application Roles

- **`deploy/ansible/roles/application/tasks/main.yml`**:

- **`deploy/ansible/roles/security/tasks/main.yml`**:

### 5. Dual Update Pathways & Zero-Data-Loss Migrations
- **`deploy/update.sh` (Remote On-Droplet Updater)**:
  - Supports `--branch`, `--skip-pull`, `--skip-migrations`, `--dry-run`, and `--help`.
  - Executes git sync, container rebuild (`docker compose build --pull`), isolated migration (`docker compose run --rm backend python manage.py migrate --noinput`), static collection, graceful container switchover, and health check validation.
  - Strictly preserves persistent volume `postgis_data`.
- **`deploy/digitalocean/scripts/update.sh` (Local CLI Runner)**:
  - Supports `--ip`, `--ssh-key`, `--user`, `--branch`, `--method` (`ssh` or `ansible`), `--dry-run`, and `--help`.
  - Auto-resolves Droplet IP and SSH key from inventory or Terraform outputs.
- **`deploy/ansible/update.yml`**:
  - Dedicated Ansible update playbook for rolling zero-downtime updates with migrations.
