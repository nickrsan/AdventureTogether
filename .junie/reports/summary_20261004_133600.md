## 1. Input Prompt & Understanding

### Input Prompt
The user requested full implementation of the **AdventureTogether** collaborative, event-based scavenger hunt platform based on the detailed requirements and technical plan in `.junie/plans/scavenger-hunt-platform.md`.

### Core Requirements
1. **Monorepo Architecture**: Clean separation into `frontend/`, `backend/`, `deploy/`, and `documentation/` with unified Docker Compose and developer workflows.
2. **Event & Team Management**: Host configuration of events with start/end windows, custom hashtags, bounding perimeters, and participant team formation via unique join codes.
3. **Geospatial Quest Builder**: Interactive map interface for hosts to draw quest target zones (points, polygons) and set criteria rules (OSM tags, Wikimedia Commons photos, Wikidata items).
4. **Foreground Ephemeral Location Sharing & Privacy**: Browser-based tracking strictly active while in the foreground, with privacy tiers (`nobody`, `team`, `quest`) and a 20-minute decay retention window.
5. **Mobile Mapping Deep Links**: Direct URL scheme generation for StreetComplete (`streetcomplete://`) and EveryDoor (`everydoor://`) pre-centered on active GPS coordinates.
6. **Multi-Platform Submission Harvester**: Background worker engine (django-q2 on PostgreSQL/PostGIS) polling OpenStreetMap Changeset API, Wikimedia Commons API, and Wikidata API matching event hashtags.
7. **Host Verification Dashboard**: Host portal with tag diff previews, external verification links, and verification checkboxes that award team points.
8. **Infrastructure & Ansible Deployment**: Multi-container Docker configuration with zero Redis overhead, and Ansible playbooks for VM security hardening, UFW firewall, and automated daily PostGIS backups.
9. **Documentation & Feature Governance**: Comprehensive user manuals and developer API documentation in `documentation/` and feature ledger in `FEATURES.md`.

## 2. Actions Taken & Code Generated

### Backend Implementation (`backend/`)
- **Django + GeoDjango Stack**: Configured Django 5 with PostgreSQL/PostGIS and SpatiaLite local fallback, Django REST Framework, GIS extensions, and `django-q2` ORM broker.
- **Domain Applications**:
  - `apps.events`: `Event` model with GeoJSON bounding polygon validation and spatial containment checks (`is_within_bounds`).
  - `apps.teams`: `Team` and `TeamMembership` models with auto-generated 6-character join codes (`generate_join_code`) and join endpoint.
  - `apps.quests`: `Quest` model with criteria type selection (`osm_tags`, `wikimedia_commons`, `wikidata_entry`), JSON validation rules, and spatial containment enforcement.
  - `apps.locations`: `LocationPing` model, foreground ingestion endpoint, privacy visibility matrix filtering (`nobody`, `team`, `quest`), and 20-minute decay cleanup routine.
  - `apps.submissions`: `Submission` model, multi-platform harvesters (`osm_harvester.py`, `wikimedia_harvester.py`, `wikidata_harvester.py`), osmChange XML diff parser, and `verify` action awarding team points.

### Frontend Implementation (`frontend/`)
- **Single Vue 3 SPA + Scoped CSS**:
  - Semantic CSS design tokens in `src/assets/styles/tokens.css` and `main.css` (zero Tailwind dependency).
  - Code-split routes in `src/router/index.ts` with lazy-loaded host modules.
  - Views:
    - `HomeView.vue`: Event discovery grid and quick links.
    - `EventMapView.vue`: Interactive Leaflet map with event bounding perimeter, quest zones, live teammate markers with last-seen timestamps, privacy visibility selector, and StreetComplete/EveryDoor deep links.
    - `JoinTeamView.vue`: Participant display name setup, team join code entry, and new team creation.
    - `HostQuestBuilderView.vue`: Interactive map drawing controls for quest target points and criteria builders.
    - `HostVerificationView.vue`: Submission review table, tag diff visualizers, external proof links, and verification toggle buttons.
  - Composables:
    - `useGeolocation.ts`: Page Visibility API integration, GPS coordinate tracking, and foreground heartbeat pings.
    - `useDeepLinks.ts`: Generates `streetcomplete://` and `everydoor://` deep link URLs.
  - API Client: Typed TypeScript REST client in `src/api/index.ts`.

### Deployment & Infrastructure (`deploy/`)
- **Docker Compose**: Zero-Redis multi-container architecture in `docker-compose.yml` and `deploy/docker-compose.yml` orchestrating PostGIS 16-3.4, Django REST API, Django-Q2 harvester worker, and Nginx Vue SPA.
- **Ansible Automation (`deploy/ansible/`)**:
  - `roles/common`: Base packages, non-root `deploy` user, project directory setup.
  - `roles/security`: UFW firewall default deny, SSH/HTTP/HTTPS whitelisting, Fail2Ban intrusion prevention.
  - `roles/postgres`: Automated daily PostGIS backup script (`backup_postgis.sh`) with 14-day retention cron job.
  - `roles/application`: Docker Compose systemd service configuration.

### Documentation & Governance
- `FEATURES.md`: Running ledger of all 10 core features marked as Completed.
- `documentation/user_guide.md`: Detailed end-user manual and host administration guide.
- `documentation/api_reference.md`: Comprehensive REST/GeoJSON developer API documentation.
